# I7 任务清单 · 切片呈现与页码

> 状态：**已完成** · 记录见 `.workbuddy/memory/2026-09-22.md`

## 目标

用户反馈「图是断的」「页码翻的时候不会变」。前两次我都判断「图完整」——
说明**判据漏掉了真实现象**。这次换判据：不再看「图形有没有被覆盖」，
而是量化「一张图被切成几片」。

## 查到的三个叠加原因

1. **细窄切片把内容切碎**（真凶）：`minSegmentHeight` 默认只有 3px，
   于是「空隙里检测到一条细线」也会生成切片。第 4 页右栏出现
   5 个 9–14px 高、整栏宽的小横条。阈值提到 20px 后消失。
2. **切片按整幅版心的统一比例缩放**：只占栏宽 76% 的架构图在 675px 版心里
   只显示 287px 还贴在左侧，右边一大片空白，看起来像「图被切掉一半」。
   改为按图自身宽度缩放（上限 1.5 倍）+ 居中。
3. **`?page=N` 深链接不滚动** → 反映为「打开第 4 页却停在第 1 页」的错觉。

## 第 4 页架构图的断裂（真正的根因）

图 3 的第一行标签（`image image image output 3x3 conv, 64 size: 224`）
被聚成一个**独立的块**（x 76→366, y 136→182），它作为障碍抢占了 y 136–182，
图形区域只能从 182 开始输出。于是同一张图被切成两片，且两片横向范围不同：

- 切片 A 来自那个文字块 → 用**整栏宽**（x 0→414）
- 切片 B 来自图形区域 → 用**图形并集**（x 111→427）

宽度不同 → 按自身宽度缩放后居中位置不同 → 「上下截成两个图错位」。

修法：**被图形区域吸收的块不再单独成为障碍**（`absorbedByFigure`，
判据是该块面积 > 30% 落在图形区域内，且它不是正文块）。
另把「并入图形区域的文字」字号上限从 0.6 放宽到 0.85 ——
图 3 的列标题 `VGG-19 / 34-layer plain / 34-layer residual` 是 0.79 倍正文，
而图注是 0.90 倍，0.85 落在两者之间、两侧各留余量。

## 效果

- 第 4 页文档流节点 19 → **12**，架构图输出为**一整片**（y 136→907）
- 全白切片 16 → **0**
- 页码跟随滚动；`?page=N` 直接滚到该页
- 新增自检项 `stats.splitFigureCount`（被切成多片且夹了译文的图形区域数，应为 0）

## 顺带发现（比 OCR 更该先补）

**`figurePathBoxes` 只看矢量路径，完全忽略位图图像。**
论文里大量图是位图（照片、热力图、截图），这类图没有矢量路径 → 检测不到 →
不会被保护成图像区域。ResNet 样本恰好全是矢量图（`paintImageXObject` 计数为 0），
所以这个缺口一直没暴露。**换一篇带照片的论文就会立刻出现。**

# I4 任务清单 · 跨栏图形

> 状态：**已完成** · 详细记录见 `.workbuddy/memory/2026-09-22.md`

## 目标
