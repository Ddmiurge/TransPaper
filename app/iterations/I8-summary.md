# I8 迭代小结 · 接入真实翻译

> 迭代：**I8** · 状态：**已完成**（浏览器 UI 层的人工目视确认待补） · 日期：2026-09-24
>
> 这是从 I0 起一直排在首位的任务。到 I7 为止，重排、排版、瀑布流都已可用，
> 唯独点开论文看到的中文是假的 —— 这一步落地后，原型才真正开始"能用"。

## 目标

把 `mockTranslate` 换掉，接上真实模型（默认 DeepSeek），并具备异步任务应有的
基本能力：并发控制、失败重试、可取消、段落级缓存、逐段回填、进度可见。

## 做了什么

### 1. 端口与适配器（分层落地）

| 层 | 文件 | 职责 |
|---|---|---|
| 领域 | `domain/translation.ts` | `TranslatorPort` 接口、缓存键、提示词、质量校验、错误分类 |
| 领域 | `domain/translationScheduler.ts` | 并发池、重试退避、取消、进度回调 |
| 基础设施 | `infra/openaiCompatible.ts` | OpenAI 兼容适配器，HTTP 状态码 → 错误分类 |
| 基础设施 | `infra/translationCache.ts` | localStorage 缓存 + LRU 淘汰 |
| 状态 | `state/translationStore.ts` | 模块级单例 + 细粒度订阅 |
| 状态 | `state/translationSettings.ts` | 服务/模型/Key/并发 设置，带逐字段类型校验 |
| 界面 | `components/TranslationBar.tsx` | 一键翻译、进度、取消、错误明细、设置面板 |

适配器覆盖 DeepSeek / Kimi / 通义 / Ollama —— 都是 `/chat/completions` 那套。
换服务只改设置里的 baseUrl 与 model。

### 2. 解决 CORS

OpenAI 兼容的模型服务都不给浏览器发 CORS 头，直连会得到 `Failed to fetch` ——
**这条报错完全推不出是 CORS 问题**。通过 Vite `server.proxy` 把 `/api/llm`
转发到真实域名。`LLM_PROXY_TARGET` 环境变量可覆盖目标，用于指向本地假服务。

### 3. 段落级缓存

键 = `provider | model | targetLang | promptVersion | hashText(source)`。
`promptVersion` 是特意加的一项：少了它，改完提示词会发现「输出没变化」，
而真实原因是命中了旧缓存 —— 这个现象会被误判成模型不听话。

实测价值：8 段文本第二轮全部命中，服务端请求数**不增加**。

### 4. 质量校验

三条保守规则：译文为空 / 译文里没有中文（模型把原文抄回来了）/ 长度比 < 0.25 或 > 2.5。
命中则**交付译文并附告警**，不自动重译 —— 误判会让人对告警整体失去信任。

### 5. 瀑布流接入

每个 `PageFlowBlock` 登记本页可译段落；`useTranslationsFor(pageBlockIds)` 按页订阅，
避免「一段译文到达 → 所有已加载页重建文档流」（150 段 × 12 页 = 1800 次含 canvas 裁切的重绘）。

默认开启**预览模式**：真实译文优先，缺失的用本地占位译文补上。
这样没配 Key 也能评估排版，而译文一到就自动覆盖。

### 集成测试里两条值得单说的断言

**「缓存有效」用服务端请求数证明，而不是看耗时。**
`expect(app.requestCount).toBe(requestsAfterFirst)` —— 耗时会被网络抖动骗过去。

**并发上限断言 `maxInFlight === 3`（不是 ≤ 3）。**
只写 `≤` 会放过「池没填满、白等」的退化；写成等号才能同时守住两个方向。

### 过程中的两个坑

**① 「并发上限 3 却观测到 4」是测试污染，不是调度器缺陷。**
起初用 `beforeAll` 共享一个假服务实例，而上一个「取消」用例留下的 `[[SLOW]]`
请求还在服务端挂着（3 秒后才响应），计数被下一个用例捡到了。
改为**每个用例一个独立实例**。计数类断言必须有干净起点 ——
假警报比漏测更坏，它会让人去改本来正确的代码。

**② 假服务的并发计数一度虚报。**
原先用 `res.on('close')` 递减，keep-alive 下 close 要等连接回收才触发，
而客户端早已收到响应发出下一个请求。改为在**响应写出的那一刻**递减。

### 未能完成的验证

**浏览器 UI 层（点击按钮后译文出现在页面上）没能自动化验证。**
无头 Edge 的 CDP 路径在本环境下失效：连上 DevTools 目标后立刻收到
`WebSocket code 1006`，且进程静默退出。既有的 `scripts/browser-verify.mjs`
（I0–I7 一直可用）也出现同样症状 —— 属于环境变化，不是本次改动引入。

处置：不再自行维护 CDP 轮子，把验证重心转到 Node 侧（集成 + 仓库两层已覆盖
UI 之下的全部接线逻辑），UI 层留给人工目视确认。

## 遗留问题

1. **API Key 存在 localStorage，不安全** —— 迁 Tauri 时必须换系统钥匙串（ADR-011 §5）
2. **无流式回填** —— 等待期间只能看进度条，看不到译文逐字出现
3. **段间术语一致性弱** —— 逐段请求没有跨段上下文，术语表（GlossaryService）未做
4. **未接真实 Key 跑过** —— 假服务与真实 DeepSeek 的响应结构一致，但真实调用仍需实测
5. **失败段落没有重试入口** —— 目前只能点「清空译文」重来（会命中缓存，只重跑失败段）
