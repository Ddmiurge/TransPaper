# I18 小结 · 块类型手动改判入口（ADR-004 欠账兑现）

> 迭代日期：2026-09-27 · 样本：two-column（e2e 用）、三基线回归
> 触发：用户确认的迭代计划（I17 表格 → **I18 手动改判** → I19 行内公式）。

## 目标

ADR-004 的原始设计是「自动判定 + 用户改判」两层：判据可以保守，因为错了用户能改。
但改判入口一直没做——任何自动判据（字号/路径/表格/公式）的误判在产品上都是死局。
I17 表格识别上线后误判面变大，这个兜底成了放开判据的前提。

## 方案

### 锚点：内容寻址，不用块 id

块 id（`p{页}-c{栏}-b{序}`）是**序号**——上游判定一变，后续块序号整体位移，
重析后 id 对不上。锚点 = `页码 + 归一化文本前缀（40 字符，空白折叠）`
（`domain/overrides.ts` 的 `anchorOf`），同一篇 PDF 重析后必然命中，且天然抗缩放。

### 双层判定 + 自动值暂存

块字段被改判覆写后，没有「自动值」就回不去了。`AutoJudgmentStash`
在每页解析后暂存各块的自动判定，改判/撤销都从暂存出发：
`applyOverrides = capture → restore → apply`，**重复套用幂等**。
关键边界：`byAnchor` 变空（撤销最后一条改判）时也必须逐块恢复——
初版在这里有提前返回的 bug，单测锁死。

### 五种类型与自动判定同语义

| 类型 | 落点 |
|---|---|
| 正文 | 正文流 + 送翻译 |
| 图表 / 表格 | `isBodyText=false`，走图像切片 |
| 公式 | 保留正文流身份、`scaleToText` 切片（同 markFormulas） |
| 文献 | 保留文本但免译（悬挂缩进渲染，同 markReferences） |

### UI 与持久化

- `PageFlowView` 在文档流根上做 `contextmenu` **事件委托**（几百个节点逐个挂监听不如根上一次），
  命中 `[data-block-id]` 才弹菜单；`FlowText` 新增 `anchor` / `overridden` 字段。
- `OverrideMenu`：选项文案写用户视角效果（翻译/保留图像/保留切片），显示当前判定与原文本预览，
  Escape/点外部关闭，视口边缘内收。
- `overrideStore`（订阅式单例，快照不可变）：文档切换整体 `setDoc` 注水/重置
  ——锚点跨文档会撞（都叫 `1|Introduction`），必须按文档隔离。
- 持久化：入库论文写 `PaperMeta.overrides`（normalizeMeta 兜底旧条目，
  `setOverrides` 全量替换）；fixture/直接打开的文件用合成 docKey 会话内生效（菜单语义上接受）。
  重复打开同一文件走去重命中，改判历史自动恢复。
