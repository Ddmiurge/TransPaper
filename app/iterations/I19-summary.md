# I19 小结 · 行内公式结构层保护（占位送译 + 回填）

> 迭代日期：2026-09-27 · 样本：single-column（公式密集，主验证）、two-column / acl（防过度占位）
> 触发：用户确认的迭代计划（I17 表格 → I18 手动改判 → **I19 行内公式**）。

## 目标

I17 先把提示词改成「行内数学逐字符照抄」，但那是**约束模型**：模型仍看得到
`f(x) = y` 的字符，仍可能把 `=` 写成「等于」、把变量译掉、或在公式里插空格。
学术阅读里这类细微变形最难发现。I19 让「公式不被翻译」在**结构层**成立。

## 方案：公式根本不进译文生成过程

```
送译前：…其中 f(x) = y 且…   →   …其中 [[MATH_0]] 且…
译后回填：…其中 [[MATH_0]] 且… →   …其中 f(x) = y 且…
```

公式字符的完整性由代码保证，而不是由模型的自律保证。

### 识别（复用现有偏移机制）

`TextSpan` 新增 `math?: boolean`，在 `paragraphBuilder` 里按三条信号标记：
1. **数学字体**：CMMI / CMSY / CMEX / MTMI / MTSY / MSAM…（剥掉子集化 `ABCDEF+` 前缀）
   ——LaTeX 公式用独立字体，这个信号比「长得像公式」可靠得多；
2. **上下标项**（判定逻辑已存在，与 `script` 同源）；
3. **数学符号占比 ≥ 0.4**（判据复用 `formulas.ts` 的 `isMathChar`，不写第二份）。

### 占位与回填（`domain/inlineMath.ts`）

- 区间直接来自 spans 偏移，**不靠文本回找** —— 否则同一段里出现两次相同的 `x` 会定位错；
- 标记用 ASCII `[[MATH_n]]` 而非 `⟦0⟧` 这类 Unicode：模型对「像模板占位」的 ASCII 复现率高得多；
- 回填**保守**：模型丢了某个标记就跳过它并返回 `missing` 计数（交给告警），
  不因回填不完整整段判失败（与 ADR-011「告警不拒绝」同原则）。

### 提示词与缓存

- 提示词新增第 4 条：`[[MATH_n]]` 原封不动搬到译文对应位置；
- **`promptVersion` 2 → 3**（ADR-011 铁律：改提示词必须递增，否则命中旧缓存会以为「改了没生效」）。

## 验证

- 单测 +12：区间提取/去重叠、占位与回填、无公式时原样返回（不影响缓存）、
  **相同公式出现两次各自占位**、丢标记的兜底、数学字体（含子集前缀）/上下标/纯正文不误标；
- 真实 PDF +2：公式密集页 7 段中 3 段标出行内公式，**最低剩余文字比例 0.98**
  （只保护了约 2% 的字符——宁可少保护也不吞正文）；ResNet 无整段被判成公式；
- 全量 **21 文件 / 205 用例** · tsc 0 错误 · build OK · 三基线回归 · I18 e2e 复跑通过。

## 踩到的坑

- **块级 spans 组装漏传 `math`**：行级已正确标出 `math:true`，但 `makeBlock`
  的 `appendSpan` 调用没带上这个参数，块级合并时被吞掉 —— 调试时对比
  lineSpans / blockSpans 才定位到。合并判据里也补了 `math` 相等条件，
  避免跨越正文把普通文字圈进公式片段。

## 遗留

- 回填后的公式在译文里是**纯文本**（没有 `<sub>/<sup>` 层级）—— 原文侧仍是完整样式。
  若要译文侧也还原上下标，需要让占位携带片段结构，属后续增强。
- 真实 Key 全文校准仍未做（用户决定放到最后），占位方案的实际效果待那次实测确认。
