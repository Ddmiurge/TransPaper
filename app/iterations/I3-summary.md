# I3 迭代小结 · 排版：从"网页卡片"改为"印刷体文档"

**日期**：2026-09-22
**主题**：让重排结果看起来像 LaTeX 编译出来的双语文档

---

## 一、用户反馈与诊断

I2 结束后内容已经正确了（图表保留、表格保留、段落切分正确），但用户看到成品后的反馈是：

> 「我希望的效果是能像 latex 一段原文，一段译文编译出来的模样。你这个下面一段绿色的框非常难看。而且重排的那些段落不像是正常的段，没有排版（比如首行缩进）。」

两条反馈都不是审美偏好，而是可诊断的缺陷：

**色块为什么错。** 它把连续的阅读流切成一节一节的方块，每读一段都要重新定位边界。而中英对照真正需要的只是"一眼分清哪段是译文"——字色就能做到，代价小得多。

**"不像正常段落"的真正原因不是少了首行缩进。** 是**行宽**。双栏论文两栏合一后行宽变成原来的两倍：150% 下内容宽 743px、字号 16.8px，即一行 44em（约 88 个西文字符）。远超书籍常规的 30–40em，回行困难，读起来就是文字墙。首行缩进只是次要因素。

**另外还有两个我自己引入的缺陷：**
- 译文字号没跟随原文 → 图注（0.9 倍）的译文比图注本身还大
- 占位译文是同一句话被截断重复 → 排版效果根本无法评估

## 二、改了什么

### 1. 去掉色块，用字色 + 间距

| | 之前 | 现在 |
|---|---|---|
| 译文样式 | 浅青底 + 左侧色条 + 圆角 | 无背景、无边框、无圆角 |
| 区分方式 | 色块 | 字色（`#31536e` 沉稳蓝灰） |
| "一对"的绑定 | 色块圈住 | 间距：译文紧跟原文（0.45em），换组拉开（1.5em） |

### 2. 行宽约束到 36em（本次最关键的一条）

```
measure = min(内容宽, 36em × 基准字号)
sliceScale = measure / 内容宽     // 图像切片等比缩到 measure 内
```

150% 缩放下：measure 从 743px → **675px**，字号 16.8 → 18.75px。图像同步缩到 0.91 倍——与 LaTeX 把图缩到版心宽度同理。

### 3. 印刷体段落

- 首行缩进：原文 1.6em，译文 2em
- 两端对齐 + 西文连字符断行
- 衬线字体栈（`Times New Roman` → `Songti SC` → `Noto Serif CJK SC`）
- 译文行距 1.8（中文需更松），原文 1.62
- 标题不缩进、不两端对齐、上下留白拉开

### 4. 恢复粗体与斜体 ⭐

论文里的**段首小标题**（`Identity vs. Projection Shortcuts.`）与**斜体术语**（`vs`、`bottleneck`）在纯文本化后会退化成正文，整段读起来没有结构。

之前认为"pdf.js 拿不到字重信息"——**这个判断是错的**：

- `textContent.styles[fontName].fontFamily` 确实只有归一化族名（serif/sans-serif/monospace）
- 但 `page.commonObjs.get(fontKey).name` 给出**真实 PostScript 字体名**：
  `NimbusRomNo9L-Medi`（粗）、`NimbusRomNo9L-ReguItal`（斜）、`NimbusRomNo9L-MediItal`（粗斜）

新增 `src/pdf/fontTraits.ts` 做名字匹配，段落模型新增 `TextSpan[]` 携带样式片段，渲染时还原为 `<strong>` / `<em>`。实测第 2 页：**粗体片段 4 个、斜体片段 7 个**。

### 5. 占位译文换成可评估的文本

改为从一组学术语体句子中按原文哈希确定性选取、拼接**完整句子**（绝不截断到句子中间），并加了"再加一句会明显超标就停"的约束，使产出长度平均约 0.55 倍原文——正是中译英的粗略字符比。

## 五、新增的坑（已固化为单测）

**样式片段的字符偏移极易错位。** 行内拼接、跨行拼接、行尾连字符还原都会改变偏移：

- 行尾连字符还原会把后续文本整体**左移一位**，片段偏移若不同步就会错位
- 拼接时补的空格如果计入片段，一个纯正文段落会被切成几十个碎片

两条都有单测覆盖（`样式片段（粗体小标题 / 斜体术语）` 一组共 4 个用例）。

另外顺手修了一个真实 bug：`Learn-` + `ing` 之间原本会插入空格变成 `Learn- ing`，导致连字符还原彻底失效。现在遇到「上一段以 `-` 结尾 + 下一段以小写字母开头」时不补空格。

## 六、已知限制

1. **样式片段依赖 PostScript 命名惯例**判断粗细，不是权威元数据。遇到自造字体名会退化为常规体（内容不错，只是样式丢失）
2. **行宽与图像尺寸被耦合**。缩窄 measure 必然缩小图像，目前不支持"正文窄 + 通栏大图"
3. **撑开 5×**（第 2 页，150%）。主要来自"左栏排完才排右栏"的纵向堆叠 + 占位译文偏长。双栏并排应能显著下降
4. 独立编号公式仍会被当正文送译
5. **翻译仍是 mock**，接入真实模型是 I4 的首要任务
