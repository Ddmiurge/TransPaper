## 一、参考文献（两条反馈，三个缺陷）

### 缺陷一：整栏文献被并成一个巨型块 —— 「挤成了一堆」

实测第 9 页：

```
行63 x=75→430 y=136→1068 :: [1] Y. Bengio, P. Simard, and P. F…   ← 63 行一段
行54 x=463→818 y=111→910 :: [28] G. Mont´ufar, R. Pascanu, K. C…  ← 54 行一段
```

根因：段落重建用「首行缩进」判段，而**参考文献用悬挂缩进**（首行顶格、续行缩进），恰好相反。
续行数量多于条目首行 → 众数落在**缩进位置** → 阈值右移到没有行能超过 → 判据一次都没触发。

**改法：把段落边界的判定从「整栏」收敛到「组内」**，两级：

1. 第一级只按纵向间隙与字号变化分组
2. 第二级在这个组内部，按**组自己的缩进结构**决定判据

判据优先级：递增的 `[N]` 序列 → 悬挂缩进 → 首行缩进（默认）。

**效果：第 9 页段数 4 → 52**，每条文献各成一段。

> 这个问题是被测试抓住的：合成用例里「顶格行与缩进行数量相当」时，
> 第一级就把文献切成每行一块（6 块而非 3 块），第二级已无从挽救。

### 缺陷二：文献条目被送去翻译

单个条目在语料特征上与正文**完全一致**（同字号、同宽度、同断点密度），
没有任何一块能独立判出来。但整个区间有明确起点：`References` 标题。

**改法：把 `translatable` 与 `isBodyText` 拆开。**

原本一个布尔同时决定「渲染成文本还是图像」和「送不送翻译」。
参考文献把这两个关注点撑开了 —— 它的正文是文本（该可选可搜索），但不该翻译。
硬用一个布尔只能二选一，两个选择都不可接受。

于是文献区间内的块：`isBodyText = true`、`translatable = false`。
区间从 `References` 标题起、到下一个真标题止，**状态跨页传递**
（`analyzePage` 收 `referencesActive` 入参、返回出状态）。

**实测第 9 页：可译段 1/51** —— 只有标题可译。第 10 页正确退出区间（附录没被吞掉）。

### 缺陷三：页码被当成标题并送去翻译

页码字号往往**大于**正文（第 9 页的 `9` 是 1.25 倍）→ 被字号判据认定为二级标题 →
作为可译内容送进流水线。页面上出现一个被译成中文的「9」。

归入 `numeric`（整块只由数字/罗马数字构成）。命名用 `numeric` 而非 `page-number`：
实测第 5 页有 12 个，它们是**表格单元格里的孤立数字** ——
叫 `page-number` 会让排查时去找一个不存在的问题。

### 渲染：文献按悬挂缩进呈现

`padding-left: 2em` + `text-indent: -2em`，字号 0.94 倍、行距收紧、不做连字符断行。
截图里每条文献首行顶格、续行缩进，**斜体期刊名保留**（`IEEE Transactions on Neural Networks`、
`BMVC`、`IJCV`），看起来就是一份文献表。

## 三、打开自己的 PDF（R1）

- 「打开 PDF」按钮 + **拖到窗口任意位置**即可打开（带覆盖层提示）
- 非 PDF 文件明确报错，而不是静默无反应
- 内置样本保留：它让「不挑文件就能验证渲染与算法」继续成立

### 顺带修掉一个只在支持打开文件后才会暴露的 bug

**块 id 是 `p{页}-c{栏}-b{序}`，不含内容。** 另一篇论文的第 1 页第 1 栏第 1 段
也叫 `p0-c0-b0` —— 不重置的话，新文档会直接把旧文档的译文显示出来。

加了 `translationStore.reset()`，换文档时清空未译队列与译文映射。
**缓存不清**：它按原文哈希索引，重新打开同一篇论文时译文会立刻从缓存回填。

## 四、顺带：浏览器验证能力恢复了

昨天记录「无头 Edge 的 CDP 路径失效」，本轮查到了真因：

```
sandbox initialization failed: Operation not permitted
GPU process exited unexpectedly: exit_code=6
FATAL: GPU process isn't usable. Goodbye.
```

**Chromium 的沙箱在这个环境里无法初始化** → GPU 进程退出 → 浏览器整个消失。
从脚本侧看到的现象只是「DevTools 端点连不上」或「连上后 WebSocket 立刻 code 1006、
进程静默退出」，极难从表象推出真因。

修法是加 `--no-sandbox --disable-gpu-sandbox`，已写进三个 CDP 脚本并附了原因说明。

**恢复后立刻用上了**，把 I8 遗留的「翻译 UI 层未验证」补齐：

```
点击「一键翻译」→ ok
进度 148/148 | 完成 148/148 段
段落 194 | 译文 144
逐段回填：第一段译文在点击后 502ms 就出现了
运行中快照：已完成 11 段时进度条为 7%（说明是增量回填）
第二次点击：所有已加载的段落都已翻译完成   ← 缓存命中
结论：✅ 翻译链路打通
```

## 六、遗留

- **R2 侧边栏与持久化仍是零进展** —— 三条需求里唯一没动的
- 文献章节标题需在词表内（`References` / `Bibliography` / `参考文献` / `引用文献`）；
  若某篇用 `Literature Cited` 会整段被翻译
- 文献条目不做结构化解析（作者/标题/期刊/年份），所以无法只译标题部分
- 表格结构未识别（表格区域整体作为图像保留）
- 跨页段落未接续；独立公式块未识别
- 位图图像检测缺失（`figurePathBoxes` 只看矢量路径）

## 七、下一迭代（I10）建议：把它变成「有文献库的软件」

这一轮解决了「打开一篇论文能好好读」。要变成真正的软件，还差**管理多篇论文**：

1. **左侧侧边栏**（R2）：论文列表、集合、标签、搜索
2. **持久化**：IndexedDB 或迁 Tauri 后的 SQLite —— 至少要让「打开过的论文」不再丢
3. 每篇论文独立保存翻译进度与阅读位置

这三件事做完，它才是「一个论文阅读软件」，而不是「一次只能读一篇的阅读器」。
