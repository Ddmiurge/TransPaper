# I2 迭代小结 · 重排质量：段落切分与图形边界

**日期**：2026-09-22
**主题**：把「重排」从"能跑"推进到"内容正确"

---

## 一、这一轮修掉的三个真实缺陷

### 1. 左右栏的行 id 撞名，导致左栏的样式分析全部用错数据 ⭐

`paragraphBuilder.ts` 生成行 id 用的是 `line-${index}`，而 `groupIntoLines` 是**按栏**调用的、`index` 在每栏内都从 0 开始。于是左栏的 `line-0` 和右栏的 `line-0` 撞名。

`analyzeTextStyle` 用 `new Map(lines.map(l => [l.id, l]))` 建索引，后写入的右栏行把左栏同名行覆盖掉。后果是：**左栏所有段落都在用右栏的字体和间隙数据做判定**，图内小字因此拿到了正文字号，一路被判成"正文"重排进文档。

第 4 页那张架构图被压平成文字墙（`image image image output 3x3 conv, 64 size: 224 ...`）就是这个 bug 的直接产物。

修复只需在行 id 里带上栏号。**一行代码，但影响面覆盖全部左栏内容。**

### 2. 段落切分不理想：巨型块与碎片同时存在

`buildParagraphs` 只用行距判段。学术论文的段落主要靠**首行缩进**标记，段间纵向空隙往往和行距一样大，于是：

- 有正文被并成一个 `y` 从 270 跨到 1069 的巨型块（40 多行、好几个自然段粘在一起）
- 同时段尾的孤立短行又被拆成独立小块

单个巨型块作为翻译单元，译文质量和"段落级对照"都无从谈起。

**加入首行缩进判据**（行左边缘比栏内主流左边缘右移超过 0.8 倍字号即视为新段首行）：

| 页 | 段数（前 → 后） | 正文段 |
|---|---|---|
| 第 2 页 | 10 → 21 | 6 → 13 |
| 第 4 页 | 11 → 38 | 8 → 10 |
| 第 6 页 | 17 → 50 | 6 → 12 |

段长回到 13/11/8/5/5 行这种正常区间。

### 3. 图形区域判定：三个方案里两个被证否

详细推理见 [ADR-009](../../docs/adr/ADR-009-vector-path-figure-detection.md)。简述：

| 方案 | 结果 |
|---|---|
| 字号判据 | ✅ 采用。图内标签实测 0.33–0.79 倍正文字号 |
| 行内断点密度 | ❌ **证否**。正文含行内公式时断点/行能到 3.3，图内标签大量是 0.0，两个分布几乎完全重叠 |
| 像素采样（文字两侧找墨迹） | ❌ **放弃**。结果随缩放漂移（100/150/200% 下分别过滤 1/3/2 个块），且无法在 Node 里测试 |
| 矢量路径聚类 + 夹住判定 | ✅ 采用。纯几何、缩放无关、可在 Node 里离线测试 |

期间还踩过一个坑：最初用「文字框与图形路径**相交**」，结果第 1 页一段 10 行正文因为某条路径从它左侧掠过就被整段保留为图像。改成「**被图形紧邻夹住**」（左右各一条 ≤3pt，或上下各一条 ≤3pt）后消失。

改成"夹住"后又短暂出现反向回归：第 6 页表 3 的数据行（字号 0.90，恰好在阈值之上）全部被判成正文。补上"上下夹住"分支后，表格行线（离文字 2–3pt）被正确识别，而图与正文之间的留白（20pt+）不会触发。

## 三、卡在哪 / 已知限制

1. **仍有 2–3 个单行块的误判**（6 页 219 段中）。典型是位于图正下方的短行，被"上下夹住"误伤（如第 1 页 `greatly benefited from very deep m…`）。属可接受范围，但要记录。
2. **公式会被当正文翻译**。行内公式（`F(x,{Wi})`) 混在段落里不可避免；独立成行的编号公式（`y = F(x, {Wi}) + x. (1)`）目前也会被抽成文本送译。这是需求 R3 中"非文本元素保持原样"的一个未覆盖项。
3. **跨页段落接续未处理**。段落被页边界截断时会变成两段。
4. **撑开 2.7–3.4 倍**。其中大部分来自"左右栏纵向堆叠"（左栏排完才排右栏），不是译文本身造成的。改为双栏并排后应能显著下降。
5. **翻译仍是 mock**（按原文长度生成的占位中文），尚未接入真实模型。

## 五、本轮的三个可复用资产

1. **`line id` 必须含栏号** —— 已固化为单测，这类"同名覆盖"bug 不靠测试根本发现不了
2. **矢量路径提取（含 CTM 追踪）** —— `operatorPaths.ts` 是纯逻辑、不 import pdf.js，因此能在 Node 里直接测。后续做表格识别、公式块识别都可以复用
3. **"按行聚合再判定"的模式** —— 在块这一层做判定太粗，在行这一层做再聚合，能把"图内标签"和"正文段落"干净分开
