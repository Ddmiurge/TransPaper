## 二、做了什么

把 I0 的「整页 canvas + 译文浮层」换成 **PageFlow 文档流**：

```
[切片: 栏顶 → 第1段底部]      ← 从整页离屏 canvas 按区域裁出，像素来自原始 PDF
[译文块: 第1段译文]           ← 普通块级元素，占多高就往下推多少
[切片: 第1段底部 → 第2段底部]
[译文块: 第2段译文]
...
```

**关键做法**：整页只渲染一次到离屏 canvas，然后按区域 `drawImage` 裁切出 N 个切片。
- 每个像素都来自原始 PDF → 图表、公式、代码**从未被重新排版**，天然「保持原样」
- 不需要块类型判定就能保住图表：段间区域作为「填充切片」被完整裁出

**关键约束**：每一栏的纵向范围被切成互不重叠的区间，合起来覆盖该栏全部内容。跨栏元素只在归属栏输出一次，在其他栏留下 skip 区间——否则同一段内容会渲染两遍。

## 四、一个反直觉的结论：不需要块类型判定

I0 小结曾判断「块类型判定必须提前成为前置依赖」，理由是「按段落切分时图表块必须整块不切」。

**这个判断被证明是多虑的。** 几何覆盖法天然解决了问题：把栏的纵向范围切成「可译段落」与「其余区域」，其余区域作为整块切片渲染——图表无论是否被识别，都会被完整保留。

因此块类型判定的优先级可以回到原计划（I4 之后），它只影响**翻译质量**（避免翻译图内标签文字），不影响**正确性**。

## 五、修掉的一个真实 bug

单测抓到：**跨栏元素把所在栏的裁切范围也撑宽了**。

一个 600px 宽的跨栏标题会让整栏的切片——包括段间的填充切片——全部变成 600px 宽，导致裁切错位。

修复：栏的裁切范围只由「归属本栏且不跨栏」的块决定；跨栏块自己用自己的宽度单独裁。这条已固化为单测。
