# I13 小结 · 位图图表与收尾页行宽

> 迭代日期：2026-09-24 · 样本：`fixtures/acl-sample.pdf`（Visual_Inception_多模态记忆投毒_ACL2026，17 页）

## 用户反馈（两个）

1. 附录部分有的图表被识别成文字
2. 最后一页段落居中、宽度只有一半没有铺满

## 根因

### 图表变文字：位图图表检测缺失（ADR-009 的最后一块拼图）

图形区域检测建立在**矢量路径**上，隐含假设「图表是画出来的」。ACL 出版排版的
图表是**整张嵌入的 PNG/JPEG**——实测全篇 17 页矢量路径 ≈ 0，图表检测整体失效：
Figure 6 的位置没有图形区域，正文流里什么都不该有却也保不住图的完整性。
（附录 P14–16 的表格是文字排版，反而靠字号判据 0.63–0.81 恰好被保留为切片。）

### 收尾页行宽缩半：行宽用了「本页内容宽」

重排行宽取本页 contentBounds——隐含假设每页内容铺满版心。附录收尾页只有
左栏有字（实测 P17 内容宽仅占页宽 37%），行宽随之缩半且居中；
同一文档各页行宽不一致，翻页时行长跳变。

## 修法

### 1. 位图放置框提取（`geometryBoxesFromOperators`）

PDF 语义：位图绘制在**单位正方形**上、由当时的 CTM 摆到页面位置。
放置框 = 单位正方形 × CTM × 视口变换。复用既有的矩阵栈追踪
（save/restore/transform/form 压栈），form 内的位图自然继承 form 矩阵。
旧 API `pathBoxesFromOperators` 保留为兼容包装。

### 2. pipeline 接入 `rawImages`

每个位图框直接作为图形区域候选——**一张嵌入的大图本身就是图形，
不需要同伴**（不受 MIN_PATHS_PER_FIGURE=4 约束）。过滤：

- 最小边长 ≥ 40 视口 px（更小的是图标/装饰）
- 面积 ≤ 85% 页面积（**整页背景图不能把整页判成图**，否则正文全灭）
- 裁剪到页面内
- 与路径簇**先合并重叠区域**再扩展（位图图表 + 矢量坐标轴共存于一图）

### 3. 位图框并入 figurePaths（关键补刀，P17 实测踩中）

区域检测到了 ≠ 会切图。空隙切图的触发条件 `gapHasFigure` 看 `figurePaths`
（切片几何的统一来源）——它只含矢量路径时，位图图表所在的纵向带
「没有图形」，整张图照样丢。位图框本身就是实打实的墨迹，直接并入。
（测试侧 realPdf 同步修改，保证与浏览器侧同一代码路径。）

### 4. 文档级行宽基准

各页就绪时上报自己的 contentBounds 宽，App 取**历史最大值**下传
（`PageFlowOptions.readingWidth`），与本页内容宽取较大者。
行宽在文档内保持稳定，翻页不再跳变；收尾页按常规行宽排。

## 顺带修掉自己刚引入的卡死

I12 的加载 effect 加了 `if (!libraryReady) return` 守卫，**依赖数组漏了
libraryReady** → 它变 true 时 effect 不重跑 → 启动永久卡在「正在加载 PDF…」。
守卫用的状态必须在依赖数组里。

## 效果（截图 `artifacts/acl-p17.png`）

- P17 Figure 6（Adversarial Attack & Defense Case Study）：完整切片呈现
- 收尾页段落铺满 685px 常规行宽，不再居中缩半
- P1/P4/P6 的位图图表同步修复（切图 264/841/312px，未覆盖路径 0）

## 遗留

- 文字排版的表格（正文同字号）仍会漏——ACL 附录表格靠字号 0.63–0.81 恰好
  被字号判据保留，同字号表格需要真正的表格结构识别
- 透明/带蒙版的背景图（水印）若小于 85% 页面积仍可能被当成图，待观察
