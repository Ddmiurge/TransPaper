# I10 小结 · 公式处理

> 迭代日期：2026-09-24 · 决策：[ADR-013](../../docs/adr/ADR-013-formulas-as-image-slices.md)

## 用户反馈

1. 公式的渲染全都有问题
2. 行间公式会被拿去翻译

## 根因与修法

### 渲染问题的两个层面

**行内公式**：上下标（$W_i$ 的 i）在 PDF 里是独立文本项——字号 0.7 倍、基线偏移。
纯拼接把它拍平成全尺寸 `Wi`，数学含义丢失。修法：`TextSpan.script` 标记 +
渲染层 `<sub>/<sup>`。

**关键实测**：下标基线只偏移 **0.15em**（第 3 页公式 (1) 的 `i`，1.49px）。
最初的 0.22em 容差恰好把它放过——脚注上标偏移更大所以能抓到，**下标全漏**。
而同一行正常项的基线在 PDF 文本矩阵里分毫不差，容差收紧到
`max(0.06em, 0.3)` 后两类都正确，零误伤。

**行间公式**：字体、间距、分式、根号全面失真——文本化对公式必然有损。
修法：回退到图像切片（ADR-008/009 既定路线），像素由原始 PDF 保证。

### 翻译问题

公式是「该保留排版但不该翻译」的内容，直接复用 ADR-012 的
`translatable = false` + `nonTranslatableReason = 'formula'` 机制。

判定用三重判据：**行尾 `(N)` 编号**（最硬）+ **数学符号密度 ≥ 0.18** +
**长单词 ≤ 2**。防误报的真正防线是长单词计数——「as shown in Table 3 (1)」
也以编号结尾，但正常句子长单词远多于公式。

## 渲染细节（都踩过坑）

- 裁切上下各扩 **0.35em**：求和/积分的上下限超出文本项 bbox，不扩会被齐腰切掉
- **不拉满行宽**：插图切片默认放大到 measure，公式会被放得离谱。
  `scaleToText` 标记 → 按 `baseFontSize / bodyFontSize` 缩放，字面高度与正文一致
- **直接输出不进 run 合并**：pageFlow 单测抓到公式段混进 run 后
  `scaleToText` 丢失（「匿名切片」携带不了缩放语义）——
  根因是 interval 上的标记没传到 segment 构造处
- 横向用整栏宽：保留公式在栏内的原始水平位置（编号右对齐）
- 自检排除：公式块**有意**以切片输出，不计入「正文重复切图」

## 效果（截图 `artifacts/formula-slice.png`）

- 公式 (1) `y = F(x,{W_i}) + x.  (1)`：真数学斜体、真下标、编号右对齐——与原 PDF 无异
- 行内 `F(x, {W_i})`、`W_sσ(W_1x)`：下标正确缩小下沉
- 公式无译文；正文 `functions²` 的脚注上标正确
- 第 3 页可译段 21 → 19（两个公式退出流水线）

类型 0 错误 · **11 文件 / 126 用例全过**（+14）· 构建正常 · 真实 PDF 无回归

## 遗留

- 多行 align / cases / 矩阵环境：行数多或混入英文时宁可漏判（维持正文流）
- 行内公式的**译文质量**未处理（翻译模型收到拍平的 `Wi`——上下标信息在
  源文本里本就丢失；彻底解决要给翻译适配器传结构化数学，属后续迭代）
- 图注与图内标签合并的块（第 2 页 `F(x)+x relu Figure 2. …`）属图形检测范畴，未动
