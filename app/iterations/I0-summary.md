## 一句话结论

**方案部分成立、部分不成立。** 坐标映射与分栏检测完全跑通（这两块是 I0 要验证的核心假设），但**「撑开式覆盖渲染」在物理上不可行**——这个发现推翻了 ADR-003 中的一个关键实现假设，但保留住了它的核心判断。

## 二、做了什么

搭了一个纯浏览器工程（Vite 8 + React 19 + pdfjs-dist 6），跑通「导入双栏 PDF → 分栏 → 重建段落 → 译文注入」的端到端链路，并配了两套自动化验证：**Node 离线校验**（算法层）与 **无头 Edge + CDP 渲染校验**（DOM 层）。

## 四、核心发现：撑开模式与覆盖式渲染互斥

### 现象

| 缩放 | 译文中位高度 | 段间可用间隙 | 结果 |
|---|---|---|---|
| 100% | 105 px | 6 px | 溢出 99 px |
| 150% | 155 px | 10 px | 溢出 145 px |
| 200% | 205 px | 13 px | 溢出 192 px |

### 根因

学术论文的段间空隙只有 **6–13 px**（这正是它排版紧凑的原因），而中文译文需要 **105–205 px**（3–5 行）。差距是 **15 倍以上**。

而更根本的问题是：**PDF 是 canvas 渲染的固定图像，译文层只能「浮」在它上面，没法把后续内容推开**。所谓「撑开模式」在覆盖式渲染里从一开始就是个不成立的选项——我在 DESIGN §6.6 里写它时没有意识到这一点。

### 这不代表覆盖式渲染整体失败

ADR-003 的核心判断仍然成立：**必须保留原 PDF 版式，才能让图表与代码「保持原样」**。失败的只是一个实现细节——把译文当作浮层，而不是文档流的一部分。

### 正确的解法（下一迭代执行）

**把 PDF 按段落切成多段 canvas，在段落之间插入真实的译文块。**

```
[canvas: 段落1 的图像]   ← 原始渲染，图表代码天然原样
[译文块: 第 1 段译文]    ← 文档流中的真实元素，会撑开
[canvas: 段落2 的图像]
[译文块: 第 2 段译文]
...
```

这样做的收益：
- 「每段原文下方紧跟译文」是**字面意义上的实现**，而不是靠定位模拟
- 段落间天然有译文空间，不再有重叠问题
- 每段仍是原始 PDF 渲染，**图表/公式/代码的「保持原样」免费获得**
- 页面会变长——这恰恰是用户期望的阅读体验（像普通文档一样往下滚）

代价：需要按 bbox 裁切 canvas 并重建文档流；页眉页脚、跨栏元素、图表块的裁切边界需要处理。这是 I1 的主要工作量。

## 五、其他实测结论

**栏检测算法**（经一次重大修正）：

第一版用「完全空白的 x 区间」找栏缝，**在真实论文上 100% 失败**——论文标题、作者行、脚注都是居中/通栏元素，横跨页面中线，把栏缝位置也标记成"已占用"。

改成**覆盖率计数法**后全部通过：不问"是否被覆盖"，而问"被覆盖了多少次"。栏缝区域只有零星几个通栏元素覆盖（计数 1–5），栏内区域被几十行正文覆盖（计数几十），量级差异非常稳定。

**已知限制**：整页图表页（第 4 页）会误检栏缝。已通过 `maxSplits: 1` 限制影响面，真正的解法留给 I1 的版面分析。

**工程踩坑记录**：

| 坑 | 表现 | 处理 |
|---|---|---|
| 下载的测试 PDF 被截断 | `InvalidPDFException: Invalid PDF structure` | 校验 `%%EOF` 与 `content-length`；curl 加 `--retry` 和更长超时 |
| `assetsInclude: ['**/*.mjs']` | pdfjs 的 `getDocument` 变成 undefined | 移除此配置；worker 用显式 `?url` 后缀 |
| `--virtual-time-budget` + Vite HMR | 无头浏览器挂死 25 分钟 | 改用 CDP 轮询等待渲染完成，不用虚拟时间 |
| macOS 无 `timeout` 命令 | 脚本静默失败 | 改用 `nohup` + 日志文件 |

## 七、下个迭代（I1）要调整什么

1. **首要任务改为「按段落切分 canvas + 文档流重排」**，而不是原计划的多论文准确率标定。理由：A4 是产品的核心体验，它不通过，标定数据没有意义。
2. 保留原有的段落重建参数标定任务（黄金数据集 20 篇），因为它决定"切在哪里"——切分位置错了，重组后的文档流也是错的。
3. 块类型判定（原 I4）的优先级需要提前：一旦按段落切分，**图表块、公式块必须被识别出来并保持整块不切**，否则切分会破坏它们。这从"可选"变成了前置依赖。
