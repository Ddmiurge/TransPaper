# I12 小结 · 论文库：侧边栏 + 持久化（R2 落地）

> 迭代日期：2026-09-24
> 这是三条核心需求里**最后一块零进展的部分**——做完它，「一次只能读一篇的阅读器」才变成「论文阅读软件」。

## 交付

### 1. 持久化（IndexedDB）

- `src/library/db.ts`：`LibraryDb` 接口 + IndexedDB 实现。**meta / files 分表**：
  侧边栏列表只读小元数据，几 MB 的 PDF 二进制只在真正打开时读取
- `src/library/libraryStore.ts`：单例 store（模式同 translationStore）。
  入库**按 fileName + byteLength 去重**（同一文件拖两次只留一条，
  重复入库会修正页数并保留原阅读进度）
- `db` 惰性创建——**不能在字段初始化时 new IdbLibraryDb()**：
  Node 测试环境没有 indexedDB，构造期的 rejection 会逃逸成
  7 个 unhandled error（vitest 退出码 1，测试明明全过）

### 2. 侧边栏（R2）

- 论文列表：标题、页数、相对时间（今天/昨天/N 天前）、**读到第 N 页**
- 搜索（标题过滤）、两步确认删除（垃圾桶 → 确认按钮，3 秒自动还原；
  不用 window.confirm —— 原生弹窗无头验证点不了）
- 当前论文高亮（左侧强调线）；工具栏「论文库」按钮收起/展开
- 正在读的论文被删除 → 自动回到内置样本，不能悬空

### 3. 启动恢复

- 文档加载 effect 等 `libraryReady` —— 恢复必须在任何加载开始前完成，
  否则会先闪一下内置样本再切换
- `?pdf=` 显式指定优先于启动恢复（开发/验证路径不受影响）
- 打开的文件顺手入库；重复打开恢复到上次的页码；翻页即写进度
  （IndexedDB 小写入便宜，不做防抖）

## 端到端验证（无头浏览器，全部通过）

```
空态 → CDP 塞真实 PDF 给文件输入框（等价于用户选择文件）
     → 入库「upload-test · 42 页 · 今天」+ 当前高亮
翻页到 6 → 整页刷新（等价于重启）
     → 自动恢复 upload-test，页码 6 / 42，侧边栏「读到 6」
搜索 zzz → 「没有匹配」；搜索 upload → 命中
两步删除 → 库清空 + 阅读器回到内置样本
```

## 测试

- `libraryStore` 6 个用例（内存 db 注入）：排序、去重、删除、进度、
  幂等通知、快照不可变
- 全库 **13 文件 / 133 用例**（+6）· 类型 0 错误 · 构建正常

## 遗留（I13 候选）

- **集合 / 标签**：R2 的完整形态还需要分组管理（数据模型已留好——meta 上加字段即可）
- 标题目前取文件名；可从 PDF 元数据 / 首页标题提取更好的标题
- 每篇论文的翻译进度没有单独保存（译文缓存按原文哈希，实际能跨会话命中）
- 论文库删除后的存储空间回收依赖 IndexedDB 自身机制
