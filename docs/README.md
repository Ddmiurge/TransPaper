# 论文阅读软件 · 架构文档集

> 本文档集是项目的**唯一架构事实来源**。开发前请按顺序通读；实现中若发现文档与代码不一致，以文档为准并提交修订。

## 产品目标

一个本地优先的论文阅读与管理工具，解决三件事：

| 编号 | 需求 | 核心难点 |
|---|---|---|
| R1 | 导入论文 PDF 文件 | PDF 无段落语义，需版面重建 |
| R2 | 左侧侧边栏归档、分类与管理 | 长期积累的个人文献库，需要关系查询 + 全文检索 |
| R3 | 一键翻译：按段落拆分 PDF，每段原文下方紧跟译文；代码块、图片、表格等非文本元素原样保留 | 渲染方案选择 + 块类型判定 |

**前端 / 渲染**：`00` → `01` → `02`（只需接口）→ `03` → `adr/ADR-008` `ADR-009` `ADR-004`

## 文档约定

- **语言**：中文正文，技术名词保留英文原词（Block、Segment、Provider 等），不翻译。
- **ADR 状态**：`Proposed`（提议）/ `Accepted`（已接受）/ `Deprecated`（已废弃）/ `Superseded by ADR-XXX`（被取代）。实现时必须遵循所有 `Accepted` 的 ADR。
- **接口定义以 TypeScript 为准**。Rust 侧接口是其等价翻译，字段名使用 snake_case。
- **图**：位于 [diagrams/](diagrams/)，为自包含 SVG，可独立打开。
- **需求编号**：正文与 ADR 中引用需求时使用 `R1` `R2` `R3`。

## 假设

本文档集建立在一个前提上：**目标形态是本地优先的桌面应用**。若项目改为 Web 应用或纯本地脚本工具，以下内容需要重做——`04` 的存储层、`05` 的进程与打包模型、`01` 中表现层与 sidecar 的隔离方式。其余部分（`02` 领域模型、`03` 数据流、`adr/ADR-002` 至 `ADR-005`）**可以完整保留**。
