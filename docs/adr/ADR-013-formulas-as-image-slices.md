# ADR-013 · 行间公式按图像切片渲染，不进翻译流水线

日期：2026-09-24 · 状态：Accepted · 关联：ADR-002（双层模型）、ADR-008（重排式渲染）、ADR-009（图形区域检测）、ADR-012（translatable 与 isBodyText 分离）

## 背景

用户反馈两个问题：

1. **公式渲染有问题**——正文里的 $W_i$ 提取后被拍平成全尺寸的 `Wi`，行间公式更是字体、间距、上下标全面失真；
2. **行间公式被送去翻译**——`y = F(x, {Wi}) + x. (1)` 被当成一个正文段落，译文毫无意义且干扰对照阅读。

## 决策

### 1. 行间公式（display equation）→ 图像切片，与图表同一条路线

ADR-008 已经确立「重排式 = 正文抽成文本 + 图形区域保留为图像切片」。公式属于
**「文本化必然有损」** 的内容：上下标拍平、斜体变量变正体、根号/分式/求和号
退化为 Unicode 字符甚至缺失。行内公式夹在正文里只能忍受，但**行间公式独立成行**，
有完整的裁切区间，完全可以回退到切片——像素由原始 PDF 保证，排版零损失。

渲染细节：

- 裁切范围 = 块 bbox **上下各扩 0.35em**（求和/积分的上下限经常超出文本项 bbox）
- 横向用整栏宽，保留公式在栏内的原始水平位置（居中或右对齐的编号）
- **不放大到行宽**：插图切片的默认行为是拉满 measure，`y = F(x)+x` 拉满会大得离谱。
  公式切片带 `scaleToText` 标记，按 `baseFontSize / bodyFontSize` 缩放，
  字面高度与两侧正文一致
- **直接输出**，不参与 run 合并——run 合并的产物携带不了缩放语义
  （这个断点被 pageFlow 单测抓到过：公式段混进 run 后标记丢失）

### 2. 判定：编号信号 + 数学符号密度 + 长单词计数（三重）

| 判据 | 内容 | 阈值 |
|---|---|---|
| 编号（最硬） | 行尾 `(N)` —— LaTeX equation 环境的普遍约定 | 配合下列两个确认信号 |
| 符号密度 | 数学符号（Unicode 数学区 + 希腊字母 + `= + { } < >`）占非空白字符比例 | ≥ 0.18 |
| 长单词 | ≥3 字母且不在数学函数白名单（sin/cos/exp/…）的单词数 | ≤ 2 |

**长单词计数是防误报的真正防线**：「as shown in Table 3 (1).」也以编号结尾，
但正常句子的长单词远多于公式。无编号公式（`equation*`）判据收紧到
「密度 ≥ 0.4 + 零长单词 + 单行」——正文里不存在这种形态。

**宁可漏判不可误判**：误判会把正文段落变成图像（不可选、不可搜），
漏判只是维持现状。多行块只要混入正文句子就整体放弃。

### 3. 行内上下标 → span 级 script 标记

上下标在 PDF 里是**独立的文本项**：字号约为主字号的 0.7 倍、基线偏移。
`TextSpan` 增加 `script?: 'sub' | 'sup'`，判定双条件缺一不可：

- 字号 < 主字号 × 0.85
- 基线偏离主基线超过 `max(0.06em, 0.3)`

**容差必须极小**——这是实测教训：下标基线只偏移约 0.15em，最初用 0.22em 容差
恰好把它放过（脚注上标偏移更大所以能抓到，下标全漏）。同一行的正常文本项
基线在 PDF 文本矩阵里**分毫不差**，0.06em 既不误伤又能抓住最浅的下标。

主基线取「主字号项」的基线，不能用行首项（行首若是上标引用标记就全错）。

### 4. 不翻译

复用 ADR-012 的机制：`translatable = false`、`nonTranslatableReason = 'formula'`。
判定顺序在 `markReferences` 之后——文献表里的公式符号密度也可能很高，
已被标记的块直接跳过，归属清晰。

## 后果

- 正面：公式排版保真、不再产出无意义译文；行内 $W_i$ 正确显示为下标
- 代价：公式不可选中、不可搜索（与图表一致，可接受——文本化版本本来就不可读）
- 遗留：多行 align 环境若被间隙切开会漏判；`cases`/矩阵环境内的换行同理；
  位图公式截图（极老论文）不适用此方案，但它本来就会被图形检测兜住
