# ADR-003: 采用覆盖式对照渲染为主，重排模式兜底

## Status

**Superseded by [ADR-008](ADR-008-reflow-as-primary-rendering.md)**（2026-09-22）

> 决策背景与推翻理由见 ADR-008。本文保留原始推理过程——其中「必须保留原 PDF 版式，图表代码才能保持原样」这一核心判断**依然成立**，被推翻的只是「覆盖式为主」的主次关系。

Accepted（2026-09-20）

## Context

需求 R3 有两条必须**同时成立**的要求：

1. 「每段原文下方紧跟对应译文」——要求原文与译文在空间上严格对应
2. 「代码块、图片、表格等非文本元素保持原样不翻译」——要求这些元素的**视觉呈现不变**

这两条同时成立，对渲染方案形成很强的约束。候选方案：

| 方案 | 做法 | 能满足 R3 吗 |
|---|---|---|
| **A. 覆盖式** | 保留原 PDF 渲染，译文以独立文本层注入原文段落 bbox 的下方 | ✅ 版式 100% 保真，图表代码天然原样 |
| **B. 重排式** | 丢弃原版式，按 Block 顺序用 HTML 重新排版，原文段与译文段交替 | ⚠️ 对照体验最好，但图表/公式/复杂表格极难还原 |
| **C. 双栏对照** | 左原文 PDF，右译文流式文本 | ❌ 不是"每段原文下方紧跟译文"，不满足 R3 的字面要求 |
| **D. 原地替换** | 把原文段落替换为译文 | ❌ 用户失去原文，违背阅读工具的基本预期 |

关键判断：**方案 B 无法满足第二条要求**。学术论文中的表格（带合并单元格、跨页）、公式（LaTeX 排版）、图表（含内部标注）一旦脱离原始版式重新排版，还原成本极高且必然失真。而"保持原样"这个需求，在方案 A 中是**免费获得**的——因为原始 PDF 根本没被改动。

## Decision

**采用方案 A：覆盖式对照渲染为主。**

具体做法：

- `ReaderView` 使用 pdf.js 渲染原始 PDF，不改动其内容
- `ParallelView` 是一个**独立于 PDF 画布的文本层**，覆盖在阅读区上方
- 译文来自 Segment，注入位置为其 `blockIds` 中**最后一个 Block 的下方**
- 译文层提供三种显示模式，按可用空间自动选择或由用户手动切换：
  1. **撑开模式**：译文占用独立空间，将后续内容向下推挤
  2. **折叠模式**：译文折叠为一行摘要，点击展开（用于阅读速度优先时）
  3. **浮层模式**：译文以浮层覆盖在原位（用于段落间空白不足时）

**同时实现方案 B 作为可切换的"重排阅读模式"。** 它不作为默认，但在以下场景是必要的逃生舱：扫描件、三层栏排版、解析质量差导致覆盖定位不准时，重排模式至少能保证文本可读。

## Consequences

### 变得更容易

- **R3 第二条要求免费达成**。代码块、图片、表格因为根本没被改动，天然"保持原样"。不需要做任何特殊处理，也不需要为每种元素类型写还原逻辑。
- **保留学术论文的版式信息**。图表位置、公式排版、双栏结构都保持原貌。这对学术阅读是重要的——很多论文的信息编码在版式里（如并排对比图、算法伪代码框）。
- **渲染实现简单**。不需要自己实现一套排版引擎，只需要在 PDF 上叠加一个定位准确的文本层。
- **用户可以随时对照原文与译文**，这在阅读需要精读的论文时是刚需。

### 变得更困难 / 需要接受

- **定位精度完全依赖解析质量**。译文错位的根本原因是 Block 的 bbox 不准或阅读顺序错乱，这不是渲染层能修的。缓解：`Document.readingOrderConfidence` 低于 0.7 时在 UI 上提示用户可切换到重排模式。
- **译文比原文长会撑破版式**。中文译文长度通常是英文原文的 0.6 - 1.0 倍，但技术术语密集时可能更长。缓解：三种显示模式 + 自动测量可用空间。
- **缩放的坐标换算容易出错**。PDF 坐标是 pt，屏幕坐标受缩放与 DPI 影响。译文层必须与 pdf.js 的 viewport 变换严格同步，否则缩放后会错位。这是实现中最容易出 bug 的地方，需要专门的测试用例。
- **页边距区域可能被侵扰**。撑开模式下推挤内容会改变页与页之间的连续性。缓解：撑开在页内进行，不跨页推挤；超出页面的译文改为浮层。
- **必须额外维护重排模式**。多一套渲染路径意味着多一套 bug 面。这是为可靠性付出的成本，但值得——没有它，解析失败的论文就完全不可用了。

### 明确放弃的东西

- 不做**原文与译文的逐句高亮联动**。粒度是段落。
- 不做**导出为 PDF**。覆盖式渲染是屏幕行为，导出走 Markdown / HTML（见 `01` 的 `ExportDocument` 用例）。因为叠加文本层的"PDF 导出"需要重新生成 PDF，收益与成本不成比例。
- 不做机器翻译直接在 PDF 上**原地替换**。用户必须能同时看到原文与译文。

### 后续可能推翻此决策的信号

如果实测发现覆盖式渲染在真实论文上的定位准确率低于 80%，说明该方案的收益被解析质量的短板吃掉了。届时应当考虑把重排模式提为默认，或引入更重的版面分析模型。**这是需要尽早用真实数据验证的风险点**，而不是留到项目后期。
