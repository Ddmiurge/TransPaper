# ADR-017: 跨页段落接续 —— 翻译单元合并而非译文切分

## Status

Accepted（2026-09-27）

## Context

段落重建是**逐页**进行的（`analyzePage` 的输入是单页文本项），一段恰好跨过页边界的
段落会被腰斩成两个块：

```
页 N 末尾：…the residual function is defined as   ← 前半段
页 N+1 顶：y = F(x) + x, where x is the input…    ← 后半段
```

两半各自成为独立翻译单元，代价是双重的：

1. **译文质量**：前半段缺下文、后半段缺上文，模型各译各的，跨界处的指代与句法断裂；
2. **排版**：后半段在重排文档里被当成新段落，误加首行缩进（`.flow-source` 的
   `text-indent: 1.6em`），读起来像凭空多出一段。

这个问题从 I6 起就登记在候选清单（「跨页段落接续」），是 R3 阅读质量的最后一块
已知欠账。实测 ResNet 样本前 12 页有 ≥2 处此类边界（I25 e2e：第 2→3 页、第 4→5 页）。

## Decision

### 1. 逐页串联判定，沿用 referencesActive 的模式

页 N 就绪时上报「段落尾部」（最后一个可译正文块），页 N+1 拿它与本页第一个可译
正文块做接续判定（`domain/crossPage.ts`）。判定成立时：

- **两半合并为一个翻译单元**：登记在后半段（宿主）的 blockId 下，原文为
  「尾块文本 + 空格 + 头块文本」；
- **尾块注销**：不再作为独立单元送译（`translationStore.unregister`）；
- **宿主块去首行缩进**：`flow-block--continued` 标记 → CSS `text-indent: 0`。

### 2. 合并译文整体显示在宿主块下，不切分回两半

瀑布流里页 N 与页 N+1 上下相接，读者实际看到的是：

```
[前半段原文]（页底）→ [页分隔线] → [后半段原文]（次页顶，无缩进）→ [整段译文]
```

这正是「一段原文一段译文」的对照结构，只是原文恰好跨过了页分隔线。

**刻意不做**「把合并译文按比例切回两半」：那需要依赖模型在接缝处输出分隔标记，
ADR-011 否决批量翻译的同一条理由适用 —— 切分错位（半句话跑到另一段）比慢严重得多。

### 3. 判据刻意保守（漏合并优于误合并）

误合并把两个无关段落搅在一起，比漏合并（现状，各译各的）更难发现也更伤信任：

- **尾部**必须以「句子未完」的字符收尾：字母/数字/逗号/分号/连接符
  （`endsOpen`）。句号、问叹号、**冒号**、引号、括号都算可结束 ——
  冒号后跟列表的情形远多于跨页延续；
- **头部**必须以小写字母/逗号/分号开头（`startsContinuation`）。**刻意不接受
  数字与左括号**：列表项（`(1) …`、`3. …`）与新段也以这些字符开头；
- 尾块与宿主块都必须是可译正文块且非标题（标题常以无标点收尾）、非行间公式；
- 中文段落头尾都无法区分延续与新段，v1 不做（行为与现状一致）。

### 4. 占位符跨块重编号

行内公式占位 `[[MATH_n]]` 的 n 是块内序号，两段各自从 0 编起。合并前尾块的
占位符必须重编号（偏移 = 头块占位数），否则回填时同一标记会把一个公式填进
两个位置（`crossPage.mergeMasked`）。合并片段经 pageFlow 的
`mergedMathPieces` 下传渲染层，译文回填用合并片段而非宿主自身的 spans。

## Consequences

- 尾块若在接续判定到达前已被单独译出（翻译先于次页加载启动），注销时其
  半段译文一并清除（`unregister` 清 byBlockId），不会与整段译文叠着显示；
- 接续判定与改判共存：尾部候选在 `applyOverrides` **之后**提取，改判把块移出
  可译集合后它自然不再是候选；
- 判据只覆盖英文形态；中文论文的跨页段落维持现状（漏合并，各译各的）。
  若未来支持中文，需要引入「次页首块无段落缩进」之类的几何信号；
- `registered` 计数在次页加载后会少 1（尾块注销 + 合并单元计入宿主），
  TranslationBar 的「已载入 N 个可译段落」随之波动，属预期。
