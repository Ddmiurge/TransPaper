# ADR-008: 重排式为默认渲染模式（取代 ADR-003 的主次关系）

## Status

Accepted（2026-09-22）· **Supersedes ADR-003**

## Context

ADR-003 在纸面上比较了「覆盖式」与「重排式」两条路线，选定了**覆盖式为主、重排式兜底**，理由是覆盖式能 100% 保住原版式，图表代码天然原样。

I0 迭代按这个方案实现后，验收项 A4（译文不压住下一段）失败：11 段中有 9 段重叠，最大溢出 879px。原因不是实现不到位，而是**方案本身在物理上不成立**：

| 缩放 | 译文需要的高度 | 段间实际空隙 |
|---|---|---|
| 100% | 105 px | 6 px |
| 150% | 155 px | 10 px |
| 200% | 205 px | 13 px |

学术论文排版紧凑，段间空隙只有 6–13px，而中文译文要 3–5 行。更根本的是：**PDF 是 canvas 渲染出来的固定图像**，译文层只能"浮"在它上面，没有任何办法把后面的内容推开。所谓"撑开模式"从一开始就不是一个可实现的选项。ADR-003 里写的"重排模式兜底"，实际是唯一可行的路径。

I1 改为重排式后，用户进一步明确要求：**不要"看起来像截图"的切片拼接，要真正的文本重排**（原文变成可选中、可搜索的真文本，类似 LaTeX 里一段原文一段译文的写法）。

## Decision

**以重排式为默认且唯一的对照渲染模式**，ADR-003 中"覆盖式为主"的定位作废。

具体形态：

```
[图像切片: 图形/表格区域]      ← 从整页离屏 canvas 按区域裁出，像素来自原 PDF
[原文块: 第 1 段（HTML 文本）]  ← 可选中、可搜索、可复制
[译文块: 第 1 段译文（HTML 文本）]
[图像切片: 下一个图形区域]
[原文块: 第 2 段]
[译文块: 第 2 段译文]
```

- **正文**抽成 HTML 文本节点，按阅读顺序单栏排布
- **图形、表格、公式**整体保留为图像切片，天然"保持原样"
- 段落之间用真实的文档流排版，"每段原文下方紧跟译文"成为**字面意义上的实现**，不再靠定位模拟

实现要点：整页只渲染一次到离屏 canvas，再按区域 `drawImage` 裁出 N 个切片。性能比逐区域渲染快一个数量级，且每个像素都来自原始 PDF，图表不会被重新排版。

## Consequences

**变得更容易：**

- A4 问题**结构性消失**——译文在文档流里，不存在"压住"的可能
- 原文可选中、可搜索、可复制，这是"阅读"而非"看图"的基本要求
- 译文长度不再受原文行高约束，长译文自然撑开

**变得更困难 / 需要接受：**

- **定位精度完全依赖解析质量**。重排把"坐标系对齐"问题换成了"段落切分"问题——段落切错，读者看到的就是错乱的对照。实测这是当前最大的质量瓶颈（见 ADR-009 与迭代小结）
- **图形区域必须能可靠识别**。覆盖式下图表永远在原位，重排式下必须主动判断"这块是图，别拆"，判错会把图表拆成散字
- **页面会变长**。一页论文重排后高度约为原来的 2–3.5 倍。这是正常的阅读体验（相当于放大字号阅读），但滚动定位、进度记录都需要按重排后的坐标来做
- 跨页段落接续、页眉页脚、页码、脚注都成为需要显式处理的问题

**何时应当推翻此决策：**

1. 若产品定位变回"忠实还原论文版式的阅读器"（例如要做批注、要按原版式引用），重排式不适用
2. 若出现必须以原版式呈现的合规要求（如引用页面对照）
3. 若重排后的解析质量长期无法达到可用阈值（段落切分正确率 < 95%），说明这条路的成本被低估了

---

## 与 ADR-003 的关系

ADR-003 中**仍然有效**的部分：

- "必须保留原 PDF 版式，图表代码才能保持原样"这个核心判断**依然成立**——重排式正是通过在图形区域回退到图像切片来满足它
- 三个候选方案的比较框架、以及排除 C（双栏对照）的理由不变

被推翻的只是**主次关系**：覆盖式从"主"降为"不采用"，重排式从"兜底"升为"唯一"。
