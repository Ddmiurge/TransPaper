# ADR-015: 文字表格以「统一切片」保留原样，不翻译

## Status

Accepted（2026-09-27）

## Context

ACL / NeurIPS 式排版的表格既不是嵌入图片、也常没有足够聚类的矢量线框，
而是「小字号（实测 0.38–0.57 × 正文）正文号文字 + 列间隙」。
现有管线把它们判成图内文字（字号判据），但因为没有几何区域，
pageFlow 只能逐行切成碎条，行间空白被丢弃 —— 表格的行列结构在视觉上散架。
这是 R3「表格保持原样不翻译」最后漏网的非文本元素（ADR-004 的兜底范围一直没覆盖到它）。

## Decision

1. **表格识别在「行」级别做**（`domain/tables.ts`）：表格行的语料特征与正文一致，
   块级判不出来；但行级有两个正文没有的几何特征 —— 一行内多个大间隙（单元格分隔）、
   间隙位置跨行对齐（共享列边界）。判据与阈值全部在 ACL 样本 p6/p14/p15/p16 上标定。
2. **识别出的表格矩形并入图形区域体系**（`figureRegions` + 调用方 `figurePaths`），
   走 ADR-008/009/013 的同一条路线：**整表一个完整切片，像素零损失，不翻译**。
   不做 HTML 表格化 —— 那需要单元格切分 + 逐格翻译的模型改动，
   且违反 R3 原始需求「表格保持原样」；留作后续增强。
3. **表格矩形必须进调用方的 `figurePaths`**：表格没有矢量路径/位图做切片几何来源，
   只进 region 不进 figurePaths 会导致空隙切图不发生（与 I13 位图框完全同一类坑）。
4. 候选行**不要求 `isBodyText`**（小字号表格行早已被标成图内文字），
   但排除公式 / 文献 / 作者 / 页码 / 标题块；**长词密度**（组平均 ≤4 个 ≥3 字母词）
   把「正文 + 行尾行内公式 / 绕排基线混入标签」的假候选排除（实测误报每行 7–9 个长词）。

## Consequences

- ACL 样本 17 页检出 11 个表格区域，全部成为单切片；
  ResNet / 单栏基线零正文块被改标（图内标签产生的区域与图形区域合并，无害）。
- 表格内容不可选中/搜索、不翻译 —— 与图片、行间公式同一取舍；
  若未来要「表格内文字可译」，需做单元格切分 + 逐格 Segment，另立 ADR。
- 误报方向的安全性质：`figureReason === 'table-region'` 只会出现在
  原本就是正文的块上，且必须 ≥50% 落在区域内；三基线守护测试断言
  ResNet / 单栏为 0。
