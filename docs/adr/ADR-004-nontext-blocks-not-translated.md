# ADR-004: 非文本块默认不翻译，且允许用户手动改判

## Status

Accepted（2026-09-20）

## Context

需求 R3 明确要求「代码块、图片、表格等非文本元素保持原样不翻译」。

这句话有两种实现路径，成本差距巨大：

| 路径 | 做法 | 成本 |
|---|---|---|
| A. 前置过滤 | 判定块类型，非文本块**根本不进入翻译流水线** | 需要一个块分类器 |
| B. 后置还原 | 全部送翻译，再想办法把不该翻的部分还原 | 几乎不可能做对——表格结构、代码缩进、公式排版一旦被 LLM 改写就无法还原 |

方案 B 在技术上不成立。因此必须走 A，而 A 的前提是**能够判定块的类型**。

问题在于：**PDF 里没有类型信息**。学术论文中：

- 表格常被识别成正文（表格线不总是被正确检测）
- 公式常被识别成图片或文本
- 参考文献条目与其他段落难以区分
- 双栏论文的页眉可能与正文文本块合并

也就是说，**块分类器必然出错**。这不是实现质量问题，而是问题本身的固有难度。

## Decision

**两条同时执行：**

1. **非文本块默认不翻译**。`translatable` 是 Block 上的布尔标志，为假时该块完全不进入翻译流水线。判定规则见 `02-domain-model.md` §4，共 11 种块类型，其中 4 种可译（paragraph / heading / caption / listItem）、7 种不可译。

2. **提供用户手动改判入口，且改判结果必须持久化**。UI 上右键即可修正块类型、切换 `translatable`、合并或拆分段落。改判会触发受影响 Segment 的缓存失效与重译。

实现细节：

- 分类器**不使用机器学习模型**（MVP 阶段），采用可解释的启发式特征：字体族与字号、跨页文本重复率、边框检测、行长度方差、符号密度、页面位置、bbox 面积占比。
- `Block.confidence` 记录判定置信度。低于阈值的块在 UI 上以弱提示标记，引导用户检查。
- `Block.overridden` 标记用户已改判。**`overridden = true` 的块不被任何自动过程覆盖**（不变量 INV-7）。
- 改判通过 `override_anchor` 表持久化，锚点由 `sha256(页号 ‖ 取整 bbox ‖ 文本前缀)` 构成，使改判在**重新解析后依然存活**（见 `04-storage-design.md` §4.4）。

## Consequences

### 变得更容易

- **R3 的要求以最直接的方式达成**。不翻译的东西根本不进流水线，不存在"翻坏了要还原"的问题。
- **成本可控**。不可译块（页眉页脚、公式、代码）往往是文档中重复度最高的内容。前置过滤还顺带减少了 token 消耗。
- **翻译质量提升**。上下文窗口里不会混入表格数据和页眉，LLM 的注意力更集中。
- **启发式分类器可调试**。每个判定都能追溯到具体特征，出错时能定位原因。相比之下，模型输出的错误往往无法解释。

### 变得更困难 / 需要接受

- **必须有改判功能的投入**。这是一个完整的 UI 功能（右键菜单、批量选择、改判后的重译提示），不是可选增强。**没有这个逃生舱，产品会在第一批复杂论文上就失去信任。**
- **需要维护 `override_anchor` 机制**。多了一张表和一套锚点计算逻辑。但省略它会导致用户校正过的判定在解析器升级后全部丢失，代价不可接受。
- **分类器需要持续用真实论文迭代**。启发式阈值需要在黄金数据集上反复校准。
- **改判有连带成本**。用户改一个块就要重译受影响的段落，需要明确提示"将重新翻译 N 段"，避免用户以为改判是免费操作。

### 明确放弃的东西

- **MVP 阶段不做表格结构识别**。表格整体作为不可译块处理，不做"提取单元格 → 翻译文本单元格 → 回填"的方案。后者需要精确的表格结构识别，投入产出比在 MVP 阶段不划算。
  - 后续可选方案：把表格渲染为图片并附一份译文表格（放在表格下方），而不是修改原表。
- **不做公式的 LaTeX 提取**。公式作为不可译块保留。
- **不做页眉页脚的自动学习**。靠"跨页文本重复率"这一启发式特征覆盖，不做跨文档的全局学习。

### 需要用户明确知晓的事

产品层面必须告知用户：**块类型识别不是 100% 准确的**。建议在首次使用时的引导中说明这一点，并指引用户如何改判。把这一限制隐藏起来只会导致用户在遇到问题时认为软件"坏了"。
