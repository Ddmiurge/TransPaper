# ADR-012: 参考文献不翻译，以及 `translatable` 与 `isBodyText` 的分离

## Status

Accepted（2026-09-24）

## Context

用户提出两点：「引用就不需要翻译了」，以及「引用似乎全都挤成了一堆」。

排查后发现这是**两个独立的缺陷**，但根因都与同一件事有关：参考文献的排版方式
（悬挂缩进）与正文相反。

### 缺陷一：整栏文献被并成一个巨型块

实测 ResNet 第 9 页：

```
[正文] ×1.00 h0 行63 x=75→430 y=136→1068 :: [1] Y. Bengio, P. Simard, and P. F…
[正文] ×1.00 h0 行54 x=463→818 y=111→910 :: [28] G. Mont´ufar, R. Pascanu, K. C…
```

一栏 63 行文献、另一栏 54 行，各自是一个块。

原因在段落重建的第一版实现：它用「首行缩进」判段 ——
先算整栏的**主流左边缘**（众数），再把明显右移的行当作段首行。
参考文献用**悬挂缩进**（首行顶格、续行缩进），恰好相反：

- 续行的数量多于条目首行 → 众数落在**缩进位置**
- 阈值随之右移到 `缩进位置 + 0.8em` → 没有任何行能超过
- 判据一次都没触发 → 整栏并成一块

### 缺陷二：文献条目被送去翻译

单个文献条目在语料特征上与正文**完全一致**：同字号（1.00 倍）、同宽度（1.00）、
同断点密度。没有任何一块能独立判出来它不该翻译。

而对文献做翻译的收益是负的：

- **作者名不能译** —— `Y. Bengio` 译成中文就没法回查了
- **文献标题译了反而有害** —— 读者要靠原题去搜原文
- **期刊名、卷号、页码是标识符**，不是自然语言

### 缺陷三：页码被当成标题并送去翻译

第 9 页的页码 `9` 字号是 1.25 倍正文 → 被字号判据认定为二级标题，
并作为可译内容送进翻译流水线。页面上出现一个被译成中文的「9」。

## Decision

### 1. 段落边界的判定收敛到**单个组内部**

原实现把「首行缩进」判据放在整栏层面。改为两级：

1. **第一级**：只按纵向间隙与字号变化分组
2. **第二级**：在这个组内部，按**组自己的缩进结构**决定用哪条判据

判据优先级：

| 顺序 | 判据 | 适用 |
|---|---|---|
| 1 | **递增的 `[N]` 序列** | 带编号的文献表。最硬 —— 编号必须递增，误判几乎不可能 |
| 2 | **悬挂缩进** | 无编号的悬挂缩进列表。缩进行占多数、顶格行占少数 |
| 3 | **首行缩进** | 默认规则，正文的形态 |

**为什么必须收敛到组内**：判定范围要与「一个语义单元」重合。
放在整栏层面时，一栏里同时包含正文与文献就必然出错 ——
整栏的主导结构是哪一种，另一类内容就得按错的规则切。

这个问题是被测试抓住的：合成用例中「顶格行与缩进行数量相当」时，
第一级就把文献切成每行一块（6 块而非 3 块），第二级已无从挽救。

### 2. `translatable` 与 `isBodyText` 分离

这是本次最重要的模型变更。

原本只有一个 `isBodyText` 布尔，它同时决定**渲染成文本还是图像**、
**送不送翻译**。参考文献把这两个关注点撑开了：

- 它的正文**是文本**（该可选中、可搜索）
- 但**不该翻译**

硬用一个布尔表示只能二选一，两个选择都不可接受：
把参考文献降级成图像（失去选中与搜索），或把 52 条文献全部送去翻译（白花钱、制造错误译名）。

因此拆成两个正交字段：

```ts
/** 决定渲染成 HTML 文本还是图像切片 */
isBodyText: boolean;
/** 决定送不送翻译 */
translatable: boolean;
/** 不翻译的原因，供渲染层选样式、供排查展示依据 */
nonTranslatableReason: 'references' | 'numeric' | null;
```

### 3. 文献区间是**区间问题**，不是分类问题

从 `References` 标题起、到下一个真标题止，整段不翻译。

- **进入**：块文本恰好等于 `References` / `Bibliography` / `参考文献` / `引用文献`
  且字号 ≥ 1.05 倍（避免正文里独立成行的这个词触发）
- **退出**：区间内遇到一个新的标题级块，且它不是以 `[N]` 开头 ——
  例如文献之后的 `Appendix A`。**没有这条判断，附录会被整段吞掉、完全不翻译**
- **状态跨页传递**：文献表常从某页栏末开始、下一页继续。
  `analyzePage` 接收 `referencesActive` 入参并返回出状态，由调用方逐页串联

### 4. 页码与表格内孤立数字归入 `numeric`

判据：整块文本只由数字（或罗马数字）构成且很短。这类内容译了没有意义。

命名用 `numeric` 而不是 `page-number`：实测第 5 页有 12 个这样的块，
它们是**表格单元格里的孤立数字**而非页码。名字叫 `page-number` 会让排查时
误以为「第 5 页怎么会有 12 个页码」，浪费时间去查一个不存在的问题。

### 5. 渲染层用悬挂缩进呈现文献

不翻译的内容改用文献的排版：`padding-left: 2em` + `text-indent: -2em`
（首行顶格、续行缩进），字号 0.94 倍、行距收紧、左对齐、不做连字符断行。

这样它看起来仍像一份文献表，而不是被重排成 52 个普通段落。

## Consequences

### 变得容易

- 用户明确要求的「引用不翻译」落地，且**作者名与文献标题保持原样可回查**
- 文献条目独立成段（第 9 页段数 4 → 52），可选中、可搜索、可逐条复制
- 页码不再被当标题、不再被翻译
- `nonTranslatableReason` 为后续「手动改判」（ADR-004 要求）提供了现成的字段与展示依据

### 变得困难 / 需要接受

- **`translatable` 是默认值语义**：非正文块（图内文字）的 `translatable` 也是 true，
  只是永远不会被登记（登记处过滤 `isBodyText && translatable`）。
  这意味着只有一处地方能看出「哪些块真的会被翻译」，排查时要记得这一层
- **文献区间的进入判据依赖标题文本**。若某篇论文的文献章节标题不在词表里
  （如 `Literature Cited`），会整段被翻译。这是保守方向上的失败，可接受
- **退出判据依赖「下一个真标题」**。若文献之后没有标题就直接结束全文，
  状态会一直保持 active —— 但那时也没有更多内容了，无影响

## 何时应当推翻此决策

- 需要翻译参考文献的**标题部分**而保留作者名与期刊名 → 需要文献条目的结构化解析
  （作者 / 标题 / 期刊 / 年份分段），远超当前的形态识别能力
- 文献章节标题词表命中率不足 → 应改为「向上找最近的标题，判断是否含 references 语义」，
  而不是继续往词表里加词
