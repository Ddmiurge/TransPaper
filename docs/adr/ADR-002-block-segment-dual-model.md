# ADR-002: 采用 Block / Segment 双层模型，分表存储

## Status

Accepted（2026-09-20）· **部分偏离（2026-09-28）**：N:1 聚合从未落地，
`Segment` 层已移除——翻译单元就是 `Block`（见 CODE_AUDIT D1）。
本 ADR 的其余内容（Block 结构、单向外键、分块存储）仍然成立。

## Context

需求 R3 要求"将 PDF 按段落拆分，输出为每段原文下方紧跟对应译文的对照格式"。

问题在于：**PDF 的文本碎片粒度 ≠ 语义段落粒度**。

PDF 格式只描述"把这段字符画在这个坐标上"，不描述段落。实际提取时会遇到：

- 一个自然段因为一处加粗、一个上标、一次换行被切成 3 个独立的文本块
- 一句话被拆分到两页
- 一段话中间夹着一个行间公式，被切成前后两块
- 图片、表格、页眉页脚的文本混在正文文本块里

如果直接拿"文本块"作为翻译单位，会得到大量破碎的烂译文；如果直接拿"整页文本"作为单位，译文会变成一大坨，无法与原文段落对齐——而需求明确要求**每段原文下方紧跟对应译文**，即对齐粒度必须是段落。

候选方案：

| 方案 | 做法 | 问题 |
|---|---|---|
| A. 单层：文本块即翻译单位 | 解析出的每个文本块直接送翻译 | 译文碎片化；跨页/跨块的段落被腰斩 |
| B. 单层：整页即翻译单位 | 每页所有文本合并送翻译 | 无法与原文段落对齐，违背 R3 的对齐要求 |
| C. 双层：Block 渲染 + Segment 翻译 | 引入两个粒度不同的抽象 | 需要维护映射关系，复杂度上升 |
| D. 三层：加"句子"层 | Block → 句子 → 译文 | 过度设计，句子级对齐对阅读体验无增量价值 |

## Decision

**采用方案 C：Block / Segment 双层模型。**

- **Block（块）= 渲染单位**。从 PDF 提取的、带坐标和类型的最小可视单元，与屏幕上的区域一一对应。携带 `bbox`、`type`、`translatable`。
- **Segment（段）= 翻译单位**。由若干 Block 按阅读顺序聚合出的语义段落。携带原文文本、缓存键、状态机。
- 两者在**数据库分表存储**，通过 `block.segment_id` 单向外键关联。
- 两者的关系由 `ParagraphBuilder`（纯函数）计算，其算法与参数见 `02-domain-model.md` §5。

关键细节：

1. **`blockIds` 的顺序不需要额外存储**。领域不变量 INV-1 保证每个可译 Block 至多属于一个 Segment，因此 `block.segment_id` 一个外键就够；顺序由 `block.read_order` 天然编码。不需要关联表，也不需要把 `blockIds` 存成 JSON。
2. **译文是独立实体而非 Segment 的字段**。因为同一段可能有多份译文（换模型重译需保留旧的做对比），且需要支持 (provider, model) 维度的缓存。
3. **译文的回填目标是 Block 而非 Segment**。渲染时按下标取 Segment 的译文，注入到其 `blockIds` 中**最后一个 Block** 的下方。

## Consequences

### 变得更容易

- **翻译质量**。送进 LLM 的是完整语义段落，不是碎片，译文可读性显著提升。
- **跨页段落处理**。可以在 Segment 层做跨页合并（见 `02` §5 的跨页续接判定），这是 Block 层做不到的。
- **改判无需重跑解析**。用户修正某个块类型时，只需在局部范围内重建受影响的 Segment，不必重新解析 PDF（解析是秒级操作，无法接受每次改判都跑一次）。
- **渲染与翻译解耦**。渲染层只需要 Block 的坐标；翻译层只需要 Segment 的文本。两者可以独立演进。
- **缓存粒度合理**。缓存键建立在段落文本上，页眉页脚等重复内容天然命中。

### 变得更困难 / 需要接受

- **必须维护 Block → Segment 的映射**。映射出错会导致译文显示在错误位置，是最主要的 bug 来源。缓解：INV-1 至 INV-3 必须由测试覆盖。
- **段落重建算法成为关键路径**。它是整个系统最容易出错、最需要反复调参的模块。缓解：设计为纯函数，用 20 篇真实论文的黄金数据集做回归门禁（见 `02` §5）。
- **失败模式是"译文错位"而非"报错"**。重建算法出错时不会抛异常，只是译文出现在错误的位置。这类静默失败最难发现。缓解：把"Block 数 → Segment 数的比例"作为核心健康指标上报（见 `01` §9），比例异常即告警。
- **段落重建必然有错**，尤其在双栏排版、跨页表格等场景。因此必须配套实现用户手动改判入口（ADR-004），否则产品会在第一批复杂论文上失去信任。

### 明确放弃的东西

- 不做**句子级对齐**。原文与译文的粒度都是段落，不做逐句对照。理由：句子级对齐对阅读体验无增量价值，却会显著增加对齐算法的复杂度与出错概率。
- 不做**段落内嵌套结构**（例如段中列表）。MVP 阶段段落是平铺的，不含子结构。
